# Automated Essay Scoring: From LSTMs to LLM Graders

We predict the score a teacher would give an essay, and measure how closely each model agrees with human raters.
The models go from simple to advanced: hand-made features → LSTM (Taghipour & Ng, 2016) → fine-tuned DeBERTa-v3 → an LLM grading with the official rubric.
Beyond accuracy, we ask whether models over-reward long essays, and how a teacher could use such a tool safely.

- **Dataset:** [ASAP-AES](https://www.kaggle.com/c/asap-aes) (Hewlett Foundation). It has 12,976 essays across 8 prompts, and each prompt uses its own score range.
- **Metric:** Quadratic Weighted Kappa (QWK), computed per prompt, averaged over 5 folds, then averaged over prompts.
- **Splits:** the 5 folds from [nusnlp/nea](https://github.com/nusnlp/nea), the paper's code, so our numbers are comparable with published work.

## Setup

```bash
git clone https://github.com/Dilip0552/essay-grader-lstm-to-llm.git
cd essay-grader-lstm-to-llm
python -m venv .venv            # then activate it
pip install -r requirements.txt -e .
cp .env.example .env            # only needed for the LLM grader (GEMINI_API_KEY)
pytest                          # should pass
```

## Data

The data and model weights are **never committed** (both are in `.gitignore`).
The competition rules allow publishing summary and analysis, but not the essays themselves. So this repo holds only essay IDs, scores and predictions, never essay text. That includes notebook outputs and logs.

1. Sign in to Kaggle, open the [asap-aes competition](https://www.kaggle.com/c/asap-aes/data), and accept the rules.
2. Download `training_set_rel3.tsv` into `data/`. Either download it from the website, or run:
   `kaggle competitions download -c asap-aes -f training_set_rel3.tsv -p data` (unzip if needed).
   The rubrics for the LLM grader are in `Essay_Set_Descriptions.zip` on the same page.
3. Run `python scripts/download_data.py`. It fetches the fold split IDs into `data/folds/` and checks everything loads.

**On Kaggle notebooks:** add the `asap-aes` competition as input, then set `ASAP_TSV=/kaggle/input/asap-aes/training_set_rel3.tsv`.

## Running experiments

Each experiment is one command and writes to `reports/results/<name>/`:

| Experiment | Command | Where / time |
|---|---|---|
| Human agreement | `python scripts/human_agreement.py` | CPU, seconds |
| Feature baselines (length-only, Ridge, LightGBM) | `python scripts/train_features.py --config configs/features.yaml` | CPU, ~3 min |
| LSTM / CNN-LSTM (Taghipour & Ng) | `python scripts/train_lstm.py --config configs/lstm_e50.yaml` (or `cnn_lstm_e50.yaml`) | 4 GB GPU, ~3 h |
| DeBERTa-v3-base | `python scripts/train_transformer.py --config configs/deberta_v3_base.yaml` | Kaggle T4 x2, ~2 h |
| BERT-base | `python scripts/train_transformer.py --config configs/bert_base.yaml` | Kaggle T4 x2, ~1.5 h |
| Per-prompt thresholds | `python scripts/optimize_thresholds.py --name deberta_v3_base` | CPU, ~2 min |
| LLM grader (Gemini, needs `GEMINI_API_KEY` in `.env`) | `python scripts/run_llm.py --config configs/llm_gemini_zero.yaml` (or `_few`) | API, ~20 min per 200 essays |
| Results table (also updates this README), analysis tables and figures | `python scripts/make_tables.py && python scripts/analyze.py` | CPU |

To run on a free GPU, open [notebooks/gpu_runner.ipynb](notebooks/gpu_runner.ipynb) in Kaggle or Colab. The setup steps are at the top of the notebook. It produces `results.zip`; unzip it into `reports/results/`.

Add `--limit 64 --epochs 1` to any training command for a quick test run (output goes to `smoke_<name>/`).

## Repo layout

```
src/aes/        data.py (loading, folds, score scaling), metrics.py (QWK), tracking.py (save predictions), models/
configs/        one YAML per experiment
scripts/        one command per experiment, plus download_data.py and make_tables.py
notebooks/      EDA, plots, and the Kaggle/Colab runner
reports/        results/ (prediction CSVs and analysis tables), figures/
tests/          pytest
```

**Rule:** every experiment saves `reports/results/<experiment>/preds_fold{k}.csv` (columns `essay_id, prompt, fold, y_true, y_pred`) through `aes.tracking.save_predictions`. Tables and plots are built only from these files.
